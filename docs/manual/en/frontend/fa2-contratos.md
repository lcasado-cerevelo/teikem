# F-A2 — Client contracts: Contract, Rates, SLA and Special services

Inside the client record (**Lists → Clients**, `/catalog/clients`, see [F-A1](fa1-clientes.md)) the **Contracts** panel went from read-only to a section with four
tabs: **Contract · Rates · SLA · Special services**. The rest of the record (header, profile, phones, people, numbering, custom fields and
history) did not change. Backend: chapter 02 of the manual, sections 4 to 6. Frontend decisions: `docs/frontend/loteFA2-decisiones.md`.
Screenshots: `img/fa2-contrato.png`, `img/fa2-sla.png`, `img/fa2-tarifas.png`, `img/fa2-especiales.png` (and `img/fa1-*.png` for the list, creation and record).

**Who can.** The **Lists** module (`CATALOG`) turned on, like the whole screen. Each part requires its permission and, without it, the button is not drawn and the fields remain read-only:

| Action | Permission |
|---|---|
| See the section (contract, rates, SLA, special services, contract history) | `contracts.read` |
| Create an additional contract (**New contract**) | `contracts.create` |
| Save details, billing model, SLA, status, rates, tiers and special services | `contracts.update` |

A user with `clients.read` but without `contracts.read` sees the full record; in **Contracts** only the billing summary and the notice “Your user cannot view
contracts (permission contracts.read)” are shown.

**Writing is only possible if the status allows it.** With the contract in a status that does not allow editing (by default **Expired** or **Cancelled**) the section shows “The contract's
current status does not allow editing; only its status can be changed.” and everything remains read-only (the server anticipates it with `canEdit`).

## 1. Section header

- **Billing:** summary of the current contract (e.g. “Per service, COD”).
- **New contract** (`contracts.create`): modal with Title (required, max. 200), Number (empty = generated by the system, `{Code}-C{n}`), **Client since**, End date,
  Currency, Billing trigger, Automatic renewal and Notes. It starts as **Draft** with “Per service” on. It does not ask for the SLA (it has its own tab). On saving, the new contract
  is selected.
- **Contract selector** (Contract, Rates and SLA tabs): lists all the client's contracts with their status and marks with “(current contract)” the one used by orders and special services; by default the current one opens.
  **Special services** belong to the client and always apply to its current contract.

## 2. Contract tab

From top to bottom:

1. **Contract status** (stages **Draft → In effect**, with **Expired** and **Cancelled** as closures). The buttons only offer the valid transitions (“Advance to …”, “Move to …”) and ask for an
   optional comment. If the server rejects (422) the message stays in the dialog.
2. **Contract details**: Number (read-only), Title, **Client since** (contract start; it decides which one is current), End date (empty = no end date; `clearEndDate`
   is sent), Automatic renewal (informational: there is no automatic expiration or renewal), Currency, Billing trigger (On pickup / On delivery / Mixed) and Notes.
   **Save** is only enabled if there are changes and sends only what changed, with the record's `rowVersion`.
3. **Billing model**: the five switches **Per service, Extra piece with special price, Dispatch fee, COD fee, Special services** and their summary.
   With **Dispatch fee** checked the fixed amount per order appears; with **COD fee** checked, the type (**Fixed ($)** or **Percent (%)**) and the value (the percentage is
   taken from the COD amount collected, not from the order total). Unchecking a switch **does not delete** what was configured: it is kept and stops being charged. A newly checked box asks for
   its amount.
4. **Status history** of the contract.

Messages (they appear under the field; the server sends them as is):

| Case | Message | HTTP |
|---|---|---|
| Empty / long title | `The contract title is required.` · `Maximum 200 characters.` | 400 |
| End earlier than start | `The end date cannot be earlier than the start date.` | 400 |
| End date and clear at the same time | `Enter an end date or mark it to clear, not both.` | 400 |
| Someone else saved first | `The contract was modified by another user; reload and try again.` — the contract is read again and what you typed is kept; press **Save** again | 409 |
| Status that does not allow editing | `The current status does not allow the action 'EDIT_CONTRACT'.` | 422 |
| Negative dispatch | `The dispatch fee cannot be negative.` | 400 |
| Negative fixed COD / percentage outside 0–100 | `The fixed COD fee cannot be negative.` · `The COD fee percentage must be between 0 and 100.` | 400 |
| Activate with the client suspended | `The contract cannot be activated: the client is suspended. Reactivate the client first.` | 422 |
| Activate with another contract already active | `The client already has a current contract. Cancel or expire the previous contract before activating this one.` | 422 |
| Repeated contract number (creation) | `A contract with the number 'X' already exists.` | 409 |
| Deactivated client (creation) | `The client has been deactivated; only its history can be viewed.` | 409 |
| Contract not found | `Contract not found.` | 404 |

## 3. SLA tab

Service levels of the contract: **one row per service type** of the list with four fields — **Maximum transit hours**, **Pickup window (min)**,
**On-time target (%)** and **Penalty ($)**. It starts empty: a type with all fields empty has no SLA.

- It is a **local draft**: nothing is sent until **Save SLA**, which sends the complete list (`PUT …/service-levels`); types without data are deactivated. **Discard changes**
  goes back to what was saved.
- On-screen validation (and the server repeats it): `Maximum transit hours must be greater than zero.` · `The pickup window (minutes) cannot be negative.` ·
  `The on-time target must be between 0 and 100.` · `The penalty cannot be negative.` (400, under the row's field). Others: `Unknown service type: 'X'.` (400) ·
  `There can only be one active service level per service type.` (409, if two people save at the same time; retry).

## 4. Rates tab

Two sections; each one is shown only if its billing model switch is checked (or if it already has rows: then it is shown but **without writes** and with a notice, because the
server rejects them). With neither of the two: “Check “Per service” or “Extra piece” in the billing model (Contract tab) to set up rates.”

**History.** Rates are effective-dated: **Edit** creates a *new version* (it closes the current one at “Effective from” and opens another; an amount is never overwritten),
**Remove** *closes* (nothing is ever deleted). The **Show history** switch also brings the closed rows (dimmed, without actions).

**“Effective from”.** By default it is today, counted in the company's day (Puerto Rico by default), which is the same the server uses; that is why, even after 8 PM, “today” is still today. When *creating* a rate it can be a past date (to load
history); in a *new version* it cannot be earlier than today.

### Rates per service
Table **Service · Package · Rate · Effective from**. **Add rate** (service, package, rate, effective from); service and package **cannot be changed** afterwards (to change them,
remove the rate and add another).

### Extra piece rates (by tier)
One block per service + package with its table of **tiers** (**Pieces** `2–5`, `6+`, **Rate**, **Effective from**). **Add extra piece** creates the block (without amount); **Add tier**
asks for *From piece* (minimum 2: piece 1 goes in the per-service rate), *Up to piece* (empty = onwards), rate and effective from. Editing a tier is a new version;
**Remove** a tier closes it, and **Remove extra piece** closes the block with all its open tiers.

| Case | Message | HTTP |
|---|---|---|
| Empty service / package / rate | `The service type is required.` · `The package type is required.` · `Enter the rate.` | screen |
| Negative rate | `The rate cannot be negative.` · `The rate per piece cannot be negative.` | 400 |
| Date earlier than today in a new version or closure | `The date cannot be earlier than today: the rate history is not rewritten.` | screen / 400 |
| There is already a current rate for the same pair | `A rate in force already exists on that date for that service and package type in the contract; edit it or close it before creating another.` | 409 |
| Component off | `The 'Per service' component is off in the contract's billing model; turn it on before working on its rates.` (and the “Extra piece” one) | 409 |
| Row already closed | `The rate is already closed; create a new one instead of editing it.` · `The component is already closed.` · `The tier is already closed.` | 409 |
| Invalid range | `Invalid range: 'from' must be at least 2 (piece 1 goes in the per-service rate) and 'to' must be greater than or equal to 'from' or left empty (open).` | screen / 400 |
| Overlapping tiers | `Tier 4–7 overlaps the current tier 2–5.` | 400 |
| New effective date or closure earlier than the row's start | `The new effective date (…) cannot be earlier than the start of the current row (…).` · `The date (…) cannot be earlier than the row's effective start (…).` | 400 |
| Nonexistent component or tier | `Rate component '<id>' not found.` · `Tier '<id>' not found.` | 404 |

## 5. Special services tab

Rate per **special service type** of the client (it applies to its current contract). Table **Service · Rate · Effective from** with **Show history**.

- **Add special service**: choose an existing type or **+ New special service type…** (“Name of the new special service” appears; the type becomes available for all
  the company's clients; if one with the same name already existed —ignoring case, accents and double spaces— it is reused). Plus the rate and “Effective from”.
- **Edit** = new version of the rate; **Remove** = close. A row's type cannot be changed. This screen does not deactivate or reactivate types.
- Writing is only possible with a current contract, “Special services” on in it and `canEdit`. If not, the rows are shown and a notice explains why there are no buttons.

| Case | Message | HTTP |
|---|---|---|
| No current contract | `The client has no current contract; create or activate a contract before setting up special services.` | 409 |
| Component off | `The 'Special services' component is off in the current contract; turn it on in the billing model to add special services.` | 409 |
| Type and new name at the same time, or neither | `Specify the special service type: an existing type (typeId) or the name of a new one (newTypeName), not both.` | 400 |
| Empty / long name | `The special service type name is required.` · `The special service type name cannot exceed 120 characters.` | 400 |
| Negative rate | `The special service rate cannot be negative.` | 400 |
| There is already a current rate for that type | `The client already has a rate in force on that date for the type 'X'; edit that rate or close it before adding another.` | 409 |
| Nonexistent / inactive type | `Special service type '<id>' not found.` (404) · `The special service type is inactive; reactivate it or choose another.` (400) | 404 / 400 |
| Last-minute duplicate type name | `A special service type with the name 'X' already exists.` | 409 |
| Row already closed | `The rate is already closed; add a new special service if you need to charge it again.` | 409 |

## Common cases
- **I don't see the tabs, only a notice**: `contracts.read` is missing. **I don't see Save / Add / Remove**: `contracts.update` is missing, or the contract is in a status that does not allow editing.
- **I saved and it says “was modified by another user”**: someone else saved first; the contract was re-read by itself and your text is still there. Review and press **Save**.
- **The extra piece rates section does not appear**: check “Extra piece with special price” in the billing model of the Contract tab.
- **I unchecked “COD fee” and the amount was lost**: it is not lost; check it again and it reappears.
- **I can't move a second contract to In effect**: a client has only one contract in In effect status at a time; cancel or expire the previous one first.
- **The quote** of an order is not on this screen: it will be done together with sales orders.
